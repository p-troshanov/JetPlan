# Канбан задач

## Назначение

Защищённый route `/kanban` показывает ту же коллекцию задач, что и основной список, но группирует её по приоритету, категории или дате. Переход между списком и канбаном сохраняет выбранный поиск и фильтры в Pinia store.

## Режимы

### Приоритет

Доска содержит три колонки: «Высокий», «Средний» и «Низкий». Перенос изменяет только `priority` через существующий `PUT /api/tasks/{id}`.

### Категория

Доска строит колонку «Без категории» и по одной колонке для каждой категории текущего пользователя. Перенос изменяет только `category_id`. Неизвестная, удалённая или чужая категория не становится доступной целью; задача с недоступной категорией остаётся видимой в «Без категории». Backend owner check остаётся обязательным source of truth.

### Дата

Основной горизонт состоит из семи локальных календарных дней: сегодня и следующие шесть дней. Дополнительные колонки «Без даты» и «Вне недели» не дают задачам исчезнуть из доступного представления. «Вне недели» принимает задачи только как исходная колонка, а «Без даты» также может быть целью и очищает `due_at`.

Фильтр «Скрыть будущие» в режиме даты не подавляет семидневный горизонт. Остальные общие фильтры, включая поиск, статус, конкретную дату, категорию, приоритет и просроченность, применяются без специальных исключений.

## Контракт времени

- Границы колонок рассчитываются по локальной timezone браузера пользователя.
- API по-прежнему получает `due_at` в ISO 8601 UTC.
- При переносе датированной задачи сохраняются её локальные часы, минуты, секунды и миллисекунды; меняются только локальные год, месяц и день.
- Преобразование выполняется стандартным `Date`, поэтому несуществующее локальное время в DST gap нормализуется JavaScript runtime к ближайшему допустимому времени.
- Задача без даты при переносе в календарный день получает 09:00 локального времени.
- `recurrence_rule`, `reminder_enabled` и `reminder_minutes` не входят в patch и сохраняются. Backend сбрасывает только `reminder_sent`, как и при любом изменении `due_at`.

## Взаимодействие и ошибки

Карточку можно перенести drag-and-drop или обычным `select` «Переместить», доступным с клавиатуры и на touch-устройствах. Изменение сначала отражается локально. Если API отвечает ошибкой или сеть недоступна, store восстанавливает предыдущую задачу, пытается перечитать коллекцию и показывает пользователю сообщение.
