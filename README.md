# Jetplan

## Серверное развёртывание

`deploy_jetplan` — серверный Bash alias для `/home/pasha/deploy_jetplan.sh`. Его нужно запускать на сервере, а не в локальном PowerShell.

Подключение к серверу выполняется через PuTTY/Pageant:

1. Запустить Pageant и убедиться, что в него загружен ключ `pasha access`.
2. Подключиться к серверу:

   ```powershell
   plink pasha@95.217.140.246
   ```

3. Уже в серверной shell выполнить:

   ```bash
   deploy_jetplan
   ```

Для неинтерактивного запуска с локальной Windows-машины используется эквивалентная команда:

```powershell
plink -batch -agent pasha@95.217.140.246 "bash -ic 'deploy_jetplan'"
```

`bash -ic` обязателен для неинтерактивного вызова: alias объявлен в серверном `~/.bashrc` и недоступен обычной удалённой команде без загрузки интерактивного Bash-окружения.

Пароля для `sudo` на сервере нет. Деплой выполняется одной командой: исполняемый файл сам обновляет проект из ветки `main`, после чего пересобирает и перезапускает контейнеры.

После выполнения задачи и релевантных проверок разрешается без дополнительного согласования создать и отправить коммит в удалённый репозиторий, а затем сразу развернуть проект командой `deploy_jetplan`.

Исключение: если изменения затрагивают только файлы `*.md`, создавать и отправлять коммит не нужно. Деплой, пересборка и перезапуск контейнеров в этом случае также не выполняются.

Если изменение требует миграций базы данных, их также разрешается выполнять без предварительного ручного создания резервной копии: резервное копирование базы данных на сервере выполняется автоматически.

Серверный контейнерный контур управляется через Podman Compose. Во всех командах и runbook следует использовать синтаксис `podman compose` без дефиса, а не отдельную команду `podman-compose`.
